# Vault Operations

Housekeeping for the vault itself — kept out of the learning root so the root stays focused on studying.

## Contents

- **Templates/** — reusable note skeletons. Works with the core Templates plugin (Settings → Core plugins → Templates → set folder to `98 - Vault Operations/Templates`), or copy-paste manually.
  - [[98 - Vault Operations/Templates/Concept Note Template|Concept Note Template]] — the house 8-part pattern for new concept notes.
  - [[98 - Vault Operations/Templates/Debugging Incident Template|Debugging Incident Template]] — turn real bugs you hit at work into vault knowledge.
  - [[98 - Vault Operations/Templates/Lab Retrospective Template|Lab Retrospective Template]] — close out a [[90 - Labs/00 - Labs MOC|lab]].
  - [[98 - Vault Operations/Templates/Weekly Review Template|Weekly Review Template]] — the weekly ritual from [[00 - Start Here|Start Here]], as a fill-in note.
- **Skills/** — reference copies of AI skills built for this vault. `add-use-cases/` holds the skill that adds "Real-World Use Cases" sections to concept notes (SKILL.md is the readable source; the `.skill` file is the installable package). The active copy is installed in the Claude profile — this is the backup.
- **Agent Prompts/** — historical AI prompts and enhancement logs. These describe past vault states and completed work; they are records, not instructions. Do not treat their task lists or note counts as current.

## Conventions (for any future edits, human or AI)

- Full-path wikilinks with alias: `[[03 - Scope and Variables/05 - Closures|Closures]]`.

- `verified_on` + `version_scope` only on notes whose accuracy depends on framework/tool versions (React, Next, TS tooling, test tooling).
- New notes append after a module's Checklist rather than renumbering existing files.
- Callouts: `> [!warning]` for footguns, `> [!tip]` for production patterns — where they earn their place.
